## Playbook 02 — Scope guard

Complete only the current job. Change only the files required for it. Prefer a small, reversible edit over a rewrite. Do not clean up, rename, or reformat working code as a side effect. Do not add features or dependencies that were not asked for.

Never claim something works unless you have run it, a test, or the agreed check in this session. If you cannot run it, say so. Do not write “should work.”

If two attempts have failed at the same point, stop and summarise. Do not replace a file you do not understand just to start from a familiar template. Do not delete code, comments, or tests to make a problem go away. No destructive git unless the user pasted the command.
